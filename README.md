# Детекция ботов по событиям пользователей — тестовое задание Авито

Решение задачи: по событиям cookie за одни сутки оценить вероятность того, что это бот. Метрика — Precision при Recall ≥ 0.70.

**Результат на платформе: 0.90251.** Файл — `submission.csv`.

Весь код, пояснения и описание подхода — в [`solution.ipynb`](solution.ipynb). Ноутбук сохранён с выводами, поэтому результаты видны без запуска.

## Идея решения в двух словах

1. **Честная подготовка данных.**
   - Отрезаю события после окна наблюдения. В train их около 17% (среди них все показы капчи), а в test таких событий нет, так что их использование было бы утечкой.
   - Удаляю полные дубли и привожу к одному виду написание платформы.
2. **Валидация по времени.** Test — следующая неделя, поэтому модель проверяется на последовательных двухдневных блоках и на семидневном блоке, обучаясь только на прошлом.
3. **130 признаков поведения** на HistGradientBoosting: ритм пауз, поиск и страницы выдачи, разнообразие объявлений, состав действий, курсор, платформа, семейство User-Agent, возраст куки.
4. **Главная находка — «пул» объявлений ботов.** Многие боты смотрят объявления из одного ограниченного набора. Признаки считают, какая доля объявлений куки встречалась у ботов за прошлые 7 дней. Метки берутся только из прошлого, test-куки друг на друга не влияют. Этот шаг поднял результат с 0.805 до 0.895.
5. **Очищенный пул и признак правдоподобия (LLR).**
   - Часть ботов смотрит случайные объявления, как люди, и засоряет пул. Поэтому пул строится только по «пуловым» ботам.
   - Признак LLR сравнивает попадания и промахи куки с тем, что типично для ботов и людей.
   - Результат — 0.90251.

Подробности, таблица всех отправок, неудачные попытки и ограничения описаны в первой ячейке ноутбука.

## Как воспроизвести

### 1. Данные

Положите файлы задания `train.csv`, `test.csv` и `events.csv.gz` в папку `data/` этого репозитория. Данные в репозиторий не включены.

Нужен Python **3.12** (3.11 тоже подходит) и около 4 ГБ свободной RAM.

### 2a. Windows 11 (PowerShell)

Откройте PowerShell **в папке репозитория**:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m jupyter lab solution.ipynb
```

Активировать окружение не нужно. Если команда `py -3.12` не найдена, сначала установите Python 3.12 с python.org.

### 2b. Linux / macOS / WSL

В терминале **из папки репозитория**:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
jupyter lab solution.ipynb
```

### 3. Запуск

В Jupyter выберите **Kernel → Restart Kernel and Run All Cells**. Ноутбук заново обучает модель и записывает `submission.csv`; готовые веса не нужны. В проверенной среде полный запуск занял около 76 секунд, на другом компьютере время может отличаться. Точное совпадение SHA-256 проверено на Linux, Python 3.12.14. Seed и число потоков зафиксированы.

В конце ноутбук сравнивает SHA-256 результата с отправленным на платформу файлом:

```text
9056acbaffed9d4605f0d09caf8d0bac9ddbadd6cb466fa54a3b7b52c8d537e3
```

Флаги в первой ячейке кода:
- `RUN_VALIDATION = False` — пропустить валидацию и быстрее получить только `submission.csv`;
- `REPRODUCE_PREVIOUS = True` — дополнительно воспроизвести отправки v4, v5 и v7 в папку `previous/` с проверкой их SHA-256. Это ещё 12 обучений.
